# Multimodal Market Signal

[![CI/CD](https://github.com/OWNER/multimodal-market-signal/actions/workflows/ci.yml/badge.svg)](https://github.com/OWNER/multimodal-market-signal/actions/workflows/ci.yml)

A small, from-scratch TensorFlow project that fuses **text** (financial
headlines) and **numeric time-series** (price/volume-derived features) to
predict next-day price direction — plus focused add-ons that demonstrate
distributed training, inference optimization, semantic retrieval, a toy
implementation of DPO (preference-based fine-tuning), and a local-first
deployment/CI setup on top of the same model.

This exists as a standalone learning/portfolio project.

> this is pushed, so the badge points at your own Actions run.

## Why this shape

Multimodal fusion of news/text sentiment with market microstructure/technical
features is a real pattern in quant and market-risk ML work, which is why
this is built around a finance use case rather than a generic MNIST-style
demo. It's structured to walk through, in order, the same story a
research/ML-engineering interview usually wants:

1. **A working multimodal model** — two input modalities, fused, trained
   end-to-end (`src/model.py`, `src/data_pipeline.py`).
2. **Distributed training** — the same model trained through TensorFlow's
   native distribution API (`src/train_distributed.py`).
3. **Inference optimization** — the trained model made smaller and faster
   for serving via post-training quantization, with a real before/after
   benchmark (`src/quantize_and_benchmark.py`).
4. **Semantic retrieval for contextual signals** — headlines embedded via
   the trained model's own text encoder, stored in a vector database
   (Pinecone, with a local fallback), so a new headline can be matched
   against similar historical headlines and their outcomes (`retrieval/`).
5. **Post-training alignment (DPO)** — a small, separate, honest
   implementation of Direct Preference Optimization's actual loss function
   on a toy sequence model (`alignment/`), since DPO doesn't apply to the
   supervised market-signal model above.
6. **Local deployment + CI/CD** — a FastAPI serving app, Docker/Compose
   for running it locally, and a GitHub Actions pipeline that runs the
   test suite and builds (and, on `main`, publishes) the Docker image
   (`serving/`, `Dockerfile`, `docker-compose.yml`, `.github/workflows/`).

## Important honesty notes 

- **The dataset is synthetic**, generated by `data/generate_synthetic_data.py`
  with a known, documented generative process (see that file's docstring).
  There was no real market data feed reachable from the environment this was
  built in. The code is written so that swapping in a real headlines +
  OHLCV dataset only requires changing the data-loading step — the model,
  training, and optimization code doesn't know or care where the numbers
  came from. Don't present this as "trained on real market data" — present
  it as "built and validated end-to-end on a synthetic dataset with the
  same shape as real headline + price data."
- **"Distributed training" here uses `tf.distribute.MirroredStrategy`**,
  TensorFlow's native data-parallel API, run on whatever hardware is
  available (this was developed and tested on CPU only, so it runs as a
  single effective replica). The *code path* — `strategy.scope()`, global
  vs per-replica batch size, dataset sharding — is exactly what you'd run
  unchanged on a multi-GPU box; only the number of visible devices changes.
  That's different from **FSDP / DeepSpeed / Megatron-LM**, which are
  PyTorch-ecosystem *model-parallel* / ZeRO-style sharding frameworks built
  for LLM-scale training that doesn't fit on one device. TensorFlow's
  closest native analogues are `tf.distribute.MultiWorkerMirroredStrategy`
  (multi-node data-parallel) and `tf.distribute.experimental` sharding
  strategies for model parallelism — mentioned and explained in
  `src/train_distributed.py`, but not claimed as equivalent to FSDP/Megatron.
  Say exactly that if asked, rather than implying this used a multi-GPU
  cluster.
- **The DPO demo is intentionally small-scale**: a tiny word-level LSTM
  language model with a frozen reference copy, trained with the real DPO
  loss on ~200 synthetic preference pairs. It's there to demonstrate
  understanding of the *mechanism* (implicit reward from log-probability
  ratios, the `beta` temperature, why you need a frozen reference model),
  not to claim RLHF-at-scale experience.
- **The retrieval embedder reuses the trained model's own text branch**
  rather than a separate pretrained sentence-embedding model — see
  `retrieval/README.md` for why, and for the explicit fallback behavior
  (and warning) when no trained model exists yet.
- **Pinecone is optional, not required to run anything in this repo.**
  `retrieval/vector_store.py::get_vector_store()` uses Pinecone only when
  `PINECONE_API_KEY` is set; otherwise everything (build_index, queries,
  the serving API, the test suite, Docker Compose) runs against a local
  numpy-based fallback store. Don't present the retrieval workflow as
  "deployed against a live Pinecone index" unless you've actually set that
  env var and built the index against it.

## Quickstart

```bash
pip install -r requirements.txt

# 1. Generate the synthetic dataset
python data/generate_synthetic_data.py

# 2. Train the multimodal model with tf.distribute
#    (also saves saved_model.keras, used by the retrieval embedder)
python -m src.train_distributed

# 3. Quantize the trained model and benchmark inference
python -m src.quantize_and_benchmark

# 4. Build the semantic retrieval index (local vector store by default;
#    set PINECONE_API_KEY to use real Pinecone instead — see .env.example)
python -m retrieval.build_index --limit 2000
python -m retrieval.query_similar "SYN00 shares surges after quarterly results"

# 5. Run the DPO toy demo (fully separate, no dependency on the above)
python alignment/dpo_toy_demo.py

# 6. Run tests
pytest tests/ -v

# 7. Serve locally
uvicorn serving.app:app --reload --port 8000
# or, in Docker / Hugging Face Spaces — start.sh trains + builds the
# index automatically on first boot if they're missing, then serves on
# $PORT (7860 by default). See DEPLOYMENT.md for the full walkthrough,
# including a free, no-credit-card Hugging Face Spaces deploy.
docker compose up --build
```
